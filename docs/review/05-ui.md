# Review 05 — UI clarity & UX (codescope-tui + the snapshot seam)

Reviewer scope: layout tiers, keymap vs the documented brief (README + research 04 + help modal),
narrow terminals, and the loading / stale / partial / deterministic surfaces — i.e. the three
trust surfaces the product promises to keep distinct (deterministic facts · approximate/partial
evidence · AI interpretation). Code is the source of truth; every claim below was verified by
reading source, and the interaction bugs were additionally reproduced by driving the public
`App`/`render` API from a scratch crate (repo untouched).

## Summary

The `codescope-tui` crate itself is well built at the mechanical level: pure `map_key`, pure
`App::apply`, layout recomputed per frame, named colors + `REVERSED`, a too-small guard, and a
width-sweep render test — all as research 04 prescribed. The genuine problems are one level up,
where the UI's *promises* meet what the snapshot seam actually delivers. Several advertised
interactions are fake or inert: scope switching changes only the top-bar label while the data
stays branch-scope; selection never drives the diff or semantic panes; `Enter`, `+`/`-` and
`n`/`N` do not do what the help modal says; and an off-by-one makes expand/collapse dead for
every file except the first. The honesty surfaces are half-wired: the refresh spinner, status
message line, scope counts, per-symbol diagnostic badges, and `LsStatus` transitions can never
change after boot, and a superseded AI view keeps rendering with no stale marking while the
status bar says `AI: idle`. None of this panics and all 365 tests pass — the tests verify the
mechanics, not the promises.

Counts: **5 high, 11 medium, 11 low**.

## Findings

### High

**H1 — Scope switching is label-only; the data never changes.**
Severity: high. `crates/codescope-tui/src/run.rs:69-75`, `crates/codescope-tui/src/app.rs:110-115`,
`crates/codescope/src/dispatcher.rs:66,120`.
`s`/`u`/`B`/`S` map to `ScopeStaged/…/ScopeCycle`, which `dispatch()` applies *locally*: only
`RefreshGit`/`AiToggle`/`AiRefresh` are forwarded to the dispatcher (run.rs:71-74). `App::set_scope`
just rewrites `self.snapshot.scope` and resets selections (app.rs:110-115). The dispatcher's own
`scope` is initialized to `ChangeScope::Branch` (dispatcher.rs:66) and is never written again, so
`repo.changeset(self.scope)` (dispatcher.rs:120) always computes the branch scope. Net effect: the
top bar says `scope: staged` over branch-scope files/diff — the UI lies — and the next publish
silently flips the label back to `branch`. README and the bottom-bar brief both advertise the keys.
Verified by scratch run (scope label changed, file rows unchanged).
Fix: make the scope actions work actions (forward to the dispatcher, which stores the scope,
recomputes the changeset, and publishes), and treat the label as dispatcher-owned state only.

**H2 — Selection never drives the diff or semantic panes; `Enter` does not do what it says.**
Severity: high. `crates/codescope/src/dispatcher.rs:326-327`, `crates/codescope-tui/src/app.rs:93-95`,
`crates/codescope-tui/src/render.rs:338`, `crates/codescope-tui/src/action.rs:42`.
The center pane is always `first_diff(a)` — the *first* file of the changeset (dispatcher.rs:326-327)
— and the right pane is either the whole impact graph or the AI rows; snapshot assembly never
sees the selection (`file_sel` only moves the highlight).
`Action::Activate` (Enter) is documented as "jump diff+semantic to it / re-center impact view"
(action.rs:42) and the help modal says "Enter — jump to symbol / re-center view" (render.rs:338),
but `App::apply` routes `Activate` into `toggle_expand()` (app.rs:93-95). With ten changed files,
`j`/`k` moves the highlight and the diff stays on file #1 forever. This breaks the core
master-detail premise of the 3-pane layout (research 04 §3: "focused diff (selected file/symbol)").
The data needed is already in `AnalysisSnapshot` (`changeset.files[i].hunks`, per-symbol graph).
Fix: either forward a `Select(entity)` action to the dispatcher, or ship all per-file diff panes in
the snapshot and let the TUI pick by selection; make `Activate` distinct from `ToggleExpand`.

**H3 — Superseded AI view keeps rendering with no stale marking (status even says `idle`).**
Severity: high. `crates/codescope/src/dispatcher.rs:92-96,225-231`, `crates/codescope-core/src/viz.rs:369`.
On `RepoChanged` the epoch is bumped and `ai_status` is reset to `Idle` (dispatcher.rs:92-96), but
`ai_rows` is kept and `panes()` renders it while *ignoring its stored epoch* — the tuple is
destructured as `(_, rows, title)` (dispatcher.rs:225). So after any edit, the semantic pane still
shows the old plan titled `… · AI` while the top bar shows `AI: idle`; nothing in the UI marks the
content as belonging to a previous repo state. `AiStatus::Stale` (viz.rs:369, "displayed plan's
epoch no longer matches; regenerating") is never set on an epoch bump — only when the provider
itself echoes a stale epoch (`codescope-ai/src/service.rs:155`). This is the display-layer version
of the bug architecture decision 4 exists to prevent, and it directly violates the "clearly marked
as interpretation / staleness" promise.
Fix: on epoch bump, compare `ai_rows.0` to the new epoch → set `AiStatus::Stale { epoch }` and
render the pane with an explicit `stale` badge (or drop the rows entirely).

**H4 — Off-by-one makes expand/collapse dead for every file except the first.**
Severity: high. `crates/codescope-tui/src/app.rs:164`.
In `toggle_expand`, after consuming the file row (`idx -= 1`), symbol rows occupy
`idx ∈ [0, symbols.len())`, but the guard is `if row.expanded && idx <= row.symbols.len()` —
`idx == symbols.len()` is the *next file row*, wrongly treated as a symbol and early-returned.
Since the dispatcher publishes every file with `expanded: true` (dispatcher.rs:309), the row after
each expanded symbol block is always the next file, so `Space`/`Enter`/`h`/`l` silently no-op on
every file row but the first. Reproduced: with `[a.go(expanded,2 syms), b.go(expanded,1)]`,
selecting `b.go` (flat index 3) and applying `ToggleExpand` leaves `b.go` expanded. The unit test
`collapse_hides_symbols` only exercises `file_sel = 0`, which is why this survived.
Fix: change the guard to `idx < row.symbols.len()`; add a test that toggles the second file.

**H5 — The status/error message surface is dead; failures are silent, and a failed first refresh
leaves the placeholder forever.**
Severity: high. `crates/codescope/src/dispatcher.rs:214,86,119-120,124-127,477`,
`crates/codescope-tui/src/snapshot.rs:28-29`, `crates/codescope-tui/src/render.rs:150-163`.
`UiSnapshot.message` ("Transient status/help message", snapshot.rs:28-29) is rendered by the bottom
bar (render.rs:150-163) but every real snapshot hardcodes `message: String::new()`
(dispatcher.rs:214); only the boot placeholder ever sets it. `Dispatcher::handle`'s doc claims
"Errors are logged and surfaced as a status message, never fatal" (dispatcher.rs:86) — they are
logged only. Consequences: an analysis failure degrades to a git-only view with zero explanation
(dispatcher.rs:124-127, `tracing::warn!` only); `AiOutcome::Unavailable`/non-renderable plans fall
to `Idle` silently (dispatcher.rs:181-183); and if the *initial* refresh errors
(`repo_context()?`/`changeset()?` at dispatcher.rs:119-120 return before any publish, and
`run()` discards the error at dispatcher.rs:477), the UI shows "scanning repository…" with a
spinner forever, with `R` failing equally silently.
Fix: route error strings into `message` (and publish a snapshot on refresh failure); the bottom
bar already supports it.

### Medium

**M1 — The refresh spinner can never appear after boot.**
Severity: med. `crates/codescope/src/dispatcher.rs:216`, `crates/codescope-tui/src/render.rs:113-115`,
`crates/codescope-tui/src/snapshot.rs:32-33`.
`refreshing` ("true while a refresh is in flight") is hardcoded `false` in every dispatcher
snapshot; only `UiSnapshot::placeholder()` sets it. Refreshes run git + gopls queries (first gopls
request timeout is 60 s, `codescope-lsp/src/gopls.rs:33`), during which the UI shows stale data with
no in-flight indication — the loading surface exists only as dead code.
Fix: publish a `refreshing: true` snapshot at refresh start and clear it at completion.

**M2 — `LsStatus` is frozen at construction: `gopls: ✓` during indexing; `Indexing`/`Degraded`
unreachable.**
Severity: med. `crates/codescope/src/dispatcher.rs:56-60`, `crates/codescope-core/src/status.rs:11-23`.
`ls_status` is set once to `Ready` (engine present) or `Failed` (absent) and never reassigned
(only read at dispatcher.rs:212). The five-state lifecycle the top bar is built to display —
`starting`, `indexing…`, `degraded` (render.rs:127-135) — can never occur, so the bar claims a
ready gopls while first queries are still slow/empty, and a degraded session (research 01 quirk 5)
still shows `✓`. Fix: update `ls_status` from engine/service signals (start, first successful
query, degradation heuristics, death via `is_alive`).

**M3 — `+` / `-` (semantic expansion depth) is inert.**
Severity: med. `crates/codescope-tui/src/app.rs:53,96-97`, `crates/codescope-tui/src/render.rs:340`.
`sem_depth` is written by `ExpandMore/ExpandLess` and read by nothing (grep: no other reference in
the workspace). The key is advertised in the help modal ("+ / - semantic depth", render.rs:340),
README, and research 04 §4. Pressing it changes nothing visible.
Fix: apply `sem_depth` when building/filtering semantic rows (snapshot assembly or render), or
remove the binding from keymap/help until implemented.

**M4 — `n`/`N` moves only a counter in the title; the diff view does not move (and the counter
resets on every publish).**
Severity: med. `crates/codescope-tui/src/app.rs:173-180`, `crates/codescope-tui/src/render.rs:219-223`.
`jump_hunk` mutates `snapshot.diff.current_hunk`, which is rendered only as `hunk 2/5` in the pane
title; `diff_scroll` is untouched, so the visible content never changes — actively confusing
feedback. Because the counter lives inside the snapshot, any dispatcher publish resets it to 1
(see M6). Fix: carry hunk-header row offsets in `DiffPane` and set `diff_scroll` on jump; keep
`current_hunk` in `App`, or derive it from scroll position.

**M5 — Expand/collapse/`Enter` act on the files pane regardless of which pane is focused.**
Severity: med. `crates/codescope-tui/src/app.rs:93-95`.
`Activate | ToggleExpand | Expand | Collapse` all call `toggle_expand()`, which operates on
`file_sel`/`files` unconditionally — `App::apply` never consults `self.focused` for them.
Reproduced: with `focused = Diff`, `Enter` toggled `a.go`'s expansion. In the medium tier the files
pane may not even be visible (semantic overlay), so keys mutate hidden state. Also, `h`/`l` are
documented as collapse/expand (action.rs:47-49) but both toggle.
Fix: route these actions per focused pane (files: expand/collapse; semantic: re-center; diff:
horizontal scroll or no-op), and make `Collapse`/`Expand` directional.

**M6 — User view state lives inside the snapshot and is clobbered by every publish.**
Severity: med. `crates/codescope-tui/src/app.rs:71-74`, `crates/codescope/src/dispatcher.rs:309`.
`App::update` replaces the whole snapshot; `expanded` flags (dispatcher always re-sends
`expanded: true`, dispatcher.rs:309), the scope label (H1), and `current_hunk` (M4) are all stored
in the snapshot, so any watcher-triggered refresh — every file save, 300 ms debounce
(`crates/codescope/src/watcher.rs:26`) — reverts the user's collapsed rows and hunk position
mid-interaction. Only `file_sel`/`sem_sel`/`diff_scroll` survive (they live in `App`).
Fix: keep interaction state (`expanded` by path, `current_hunk`, scope) in `App`, keyed to stable
ids, and reconcile on snapshot replace, as research 04 §5 implies ("open/close tracked by stable ids").

**M7 — AI controls misreport availability: toggle isn't inert without config; failure reason and
throttling are invisible.**
Severity: med. `crates/codescope/src/dispatcher.rs:101-109,152-157,178-183`,
`crates/codescope-tui/src/action.rs:64`, `crates/codescope-tui/src/render.rs:137-146`.
`Action::AiToggle` is documented "inert when AI is not configured" (action.rs:64), but the
dispatcher flips `ai_enabled` and publishes `AiStatus::Idle` even when `self.ai` is `None`
(dispatcher.rs:101-109) — the bar then claims `AI: idle` (available) though `A` will no-op forever
(refresh_ai's `let (Some(ai), …) else return`, dispatcher.rs:152-153). `AiStatus::Failed { reason }`
carries a status-line-safe reason that is never displayed (`ai_label` → literal `"failed"`,
render.rs:144; `message` dead per H5), and `AiOutcome::Unavailable` (circuit open/throttle) maps to
plain `Idle` (dispatcher.rs:181-183). Fix: keep `Disabled` when unconfigured (set `message` to
"AI not configured"), surface `reason` in the bottom bar, and give `Unavailable` its own label.

**M8 — The AI surface renders only a title + bare labels: focus, summary, edges, and validation
drops are all discarded.**
Severity: med. `crates/codescope/src/dispatcher.rs:169-173,225-231,425-445`,
`crates/codescope-core/src/viz.rs:38,123-125`.
`plan_rows` flattens `forms[0].nodes` into labels; `plan.focus` (the single question the plan
answers, viz.rs:38), `VizForm.summary` (≤3 lines, doc: "rendered next to the visual",
viz.rs:123-125), `edges` (flow/sequence forms), and any second form are dropped. The
`ValidationReport` is checked for renderability then discarded (dispatcher.rs:169-172), so a
`ValidWithDrops` plan shows no hint that nodes were removed; the pane `note` is explicitly emptied
for AI content (dispatcher.rs:229), losing even the partial-data caveat the deterministic path
shows. The "AI interpretation, clearly marked" surface reduces to a two-character `· AI` title
suffix. Fix: render focus/summary as the pane note (or header rows), and add a drops note from the
validation report.

**M9 — Diff scrolling breaks on wrapped lines: `G` cannot reach the bottom; horizontal scroll was
specified instead of wrap.**
Severity: med. `crates/codescope-tui/src/render.rs:248-251`, `crates/codescope-tui/src/app.rs:131-135,145-152`.
The diff `Paragraph` enables `Wrap { trim: false }` with `.scroll((diff_scroll, 0))`. The scroll
clamp counts *logical* rows (`rows.len()-1`), while a wrapped paragraph scrolls in *visual* lines,
so on long-line diffs `G`/`Bottom` stops well above the end. Reproduced headlessly: 6 rows of
100-char adds at 40×12, `Bottom` → last row not in the buffer; with short lines it is. Wrapped
continuation lines also restart at column 0, breaking the gutter/±alignment that makes a diff
readable. Research 04 §5 explicitly chose `Paragraph::scroll` *both axes* over wrapping ("diff
lines are long"); the x offset is hardcoded 0 and no key maps to horizontal scroll.
Fix: drop `Wrap`, add h-scroll keys (or clamp against a wrapped-height calculation).

**M10 — Boot blocks on the gopls initialize handshake (up to 60 s) before the TUI appears.**
Severity: med. `crates/codescope/src/main.rs:57-68,97`, `crates/codescope-lsp/src/gopls.rs:33,81`.
The comment says "Start the language server in the background; the UI is usable before it is
ready" (main.rs:57), but `LanguageService::start` — process spawn + `initialize` request with
`FIRST_REQUEST_TIMEOUT = 60s` — is awaited inline *before* `ratatui::init()` runs (main.rs:97).
On a large module the user stares at an untouched terminal with no feedback; the placeholder
snapshot exists precisely for this phase but can't be shown yet.
Fix: start the TUI first and hand the engine to the dispatcher when ready (`LsStatus::Starting`
until then — see M2).

**M11 — Per-symbol diagnostic badges can never appear in the files pane.**
Severity: med. `crates/codescope/src/dispatcher.rs:299`, `crates/codescope-tui/src/snapshot.rs:120-121`,
`crates/codescope-tui/src/render.rs:184`.
`SymbolRow.has_diagnostic` ("a diagnostic touches this symbol") is hardcoded `false` at assembly,
though `AnalysisSnapshot.diagnostics` is populated and the impact graph is annotated
(`codescope-analysis/src/engine.rs:62`, `graph.rs:165`). The red `!` badge in the files pane
(render.rs:184) is unreachable; diagnostics only ever surface on impact rows.
Fix: intersect diagnostics with changed-symbol ranges during `file_rows`.

### Low

**L1 — `scope_counts` is never populated and never rendered; empty scopes give no cross-scope hint.**
Severity: low. `crates/codescope/src/dispatcher.rs:273`, `crates/codescope-tui/src/snapshot.rs:16-17,87-96`
(no reference in render.rs).
The field documented "for the scope switcher in the top bar" is `ScopeCounts::default()` at
assembly and unused by the renderer. A user in an empty scope sees "no changes in this scope"
(render.rs:197-201) with no indication that `staged: 2` exists one keypress away.
Fix: compute the three changesets' counts and render `branch 4 · staged 2 · unstaged 0`.

**L2 — Trust markers have no in-app legend, and `?` means three different things.**
Severity: low. `crates/codescope-tui/src/render.rs:91,189,325-345`, `crates/codescope-tui/src/snapshot.rs:103,118-119`,
`crates/codescope/src/dispatcher.rs:317`.
`~` (approximate), `?` (unmapped), `!` (diagnostic), yellow (changed), `· AI`, and `ⓘ` are nowhere
explained — the help modal lists keys only. Meanwhile `?` is also the file badge for
Added/Untracked (dispatcher.rs:317) *and* the unknown-base placeholder (render.rs:91). The
`SymbolRow` docs promise an `A` badge (snapshot.rs:103) that the assembler never emits, leaving
`status_style`'s `"A"` arm unreachable (render.rs:388).
Fix: one legend section in the help modal; use `A` for added files; pick a different unknown-base
placeholder.

**L3 — Layout tiers ignore height where research specified it; bars never drop at low heights.**
Severity: low. `crates/codescope-tui/src/render.rs:35,46,25-30`.
Wide requires `w ≥ 120 && h ≥ 20` (per research), but medium is `w ≥ 80` at *any* height — research
04 §3 says `h < 15` → narrow — and the "help bar may drop out below h = 12" adjustment was never
implemented (top+bottom bars always reserved). Benign (the sweep test proves no panics; cassowary
absorbs it), but at e.g. 100×10 two bordered panes get ~6 content rows while 2 rows go to bars.
Fix: fold height into the medium/narrow split and drop the bottom bar below h≈12.

**L4 — `Esc` does not dismiss the medium-tier semantic overlay.**
Severity: low. `crates/codescope-tui/src/action.rs:102`, `crates/codescope-tui/src/render.rs:52-54`.
The overlay appears whenever `focused == Semantic` at 80–119 cols; it looks like a popup (Clear +
centered) but only `Tab`/`1`/`2` remove it; `Esc` maps to `Action::None`. The help modal *does*
close on Esc, so the convention is inconsistent.
Fix: map Esc → `Focus(Files)` (or previous pane) when the overlay is showing.

**L5 — Top bar clips its most transient indicators first on narrow terminals.**
Severity: low. `crates/codescope-tui/src/render.rs:89-116`.
The bar is one unwrapped `Paragraph`; overflow clips from the right, where the AI status and the
refresh spinner `⟳` are appended last (render.rs:112-115). In the narrow tier the bar routinely
exceeds width (repo + branch + base + scope + gopls + AI), so exactly the loading/AI surfaces
vanish. Fix: tier-aware top bar (drop repo/base details before status glyphs).

**L6 — Diff pane has no empty state and no binary-file notice.**
Severity: low. `crates/codescope-tui/src/render.rs:216-252`, `crates/codescope/src/dispatcher.rs:326-356`.
`DiffPane::default()` renders a blank untitled pane (files/semantic panes both have placeholder
text, render.rs:197-201,297-302). `FileChange.binary` is never consulted, so a binary change shows
an empty diff with no explanation.
Fix: add "no diff selected" / "binary file (no text diff)" placeholder rows.

**L7 — Continuous 30 fps redraw with a full snapshot clone and styled-line rebuild every frame.**
Severity: low (perf/energy; overlaps review 06/perf). `crates/codescope-tui/src/run.rs:32,35`,
`crates/codescope-tui/src/render.rs:226-246`.
The tick is 33 ms (research 04 recommended 250 ms) and each iteration runs
`render(frame, &app, &app.snapshot.clone())` — a deep clone of every diff/semantic row — then
rebuilds all `Line`s (research 04 pitfall 5: cache styled lines on data change). Nothing animates
(the spinner glyph is static), so the machine burns CPU for identical frames. The
`(&App, &UiSnapshot)` double-parameter where run always passes `app.snapshot` is the API smell
that forces the clone.
Fix: 250 ms tick + draw-on-change, `render(frame, &app)` reading `app.snapshot`, cache lines.

**L8 — Declared-but-unused dependencies: `tui-tree-widget`, `unicode-width`.**
Severity: low. `crates/codescope-tui/Cargo.toml:12,17`.
Neither crate is referenced anywhere in the workspace (grep). The tree widget was the research
recommendation for the impact pane; a hand-rolled guide renderer shipped instead (fine, testable).
Fix: remove the deps (or adopt the tree widget when the semantic pane becomes a real tree).

**L9 — Help modal gaps: `Shift-Tab` and `Home`/`End` undocumented; `q` swallowed while open;
clips on small terminals.**
Severity: low. `crates/codescope-tui/src/render.rs:322-355`, `crates/codescope-tui/src/action.rs:85-90`.
The modal (15 content lines) omits `Shift-Tab` (README documents it) and `Home`/`End`; while open,
every key except `?`/`Esc` — including `q` — is swallowed (action.rs:85-90), and at small sizes the
70 %×70 % popup truncates the key list with no scroll. Fix: add the two lines, let `q` quit from
the modal, and size the popup to content with a minimum.

**L10 — Ahead/behind counts can describe a different ref than the displayed base, and `+2 -0`
reads as a diffstat.**
Severity: low. `crates/codescope/src/dispatcher.rs:250-259`, `crates/codescope-tui/src/render.rs:98-103`.
`base` prefers `ctx.base` falling back to upstream, while `ahead/behind` always come from
`ctx.upstream` — the pair can be mismatched next to each other in the bar. `+n -m` next to a diff
tool strongly suggests added/removed lines; `↑n ↓m` is the established ahead/behind idiom.
Fix: derive counts from the same ref that is displayed; use arrows.

**L11 — Page/half-page sizes are hardcoded (20/10 rows) instead of viewport-derived.**
Severity: low. `crates/codescope-tui/src/app.rs:87-90`.
`Ctrl-d`/`PgDn` scroll fixed amounts regardless of pane height: ~2 pages on a 12-row terminal,
40 % of a 50-row one. `App` never learns the viewport height (render-only layout), which is why —
but a last-known-height field set during render (or an action carrying the height) fixes it.

### The three trust surfaces, assessed

- **Deterministic/verified**: structurally present (impact rows, confidence markers, real symbol
  names) but under-delivered — diagnostics badges dead in the files pane (M11), `LsStatus` frozen
  (M2), markers unexplained (L2).
- **Approximate/partial**: the only live caveat is the generic "partial: some relationships
  unavailable" note (dispatcher.rs:398-402). The specific caveats built for the UI —
  `Evidence.notes` ("Carried end-to-end to the UI", `codescope-core/src/relation.rs:84`) and
  per-file `FileAnalysis.notes` (`codescope-analysis/src/engine.rs:43`) — never reach the screen.
- **AI interpretation**: marked only by a `· AI` title suffix; staleness unmarked with a
  contradicting `idle` status (H3); focus/summary/validation-drops discarded (M8); failure reasons
  invisible (M7). This is currently the weakest of the three surfaces.

### What is genuinely good (no action)

Pure `map_key` + `App::apply` with real tests; per-frame layout recompute; 4-tier structure with a
too-small guard and a width/height sweep test; named colors + `REVERSED` selection (theme-safe);
focus-styled borders; empty-state text in files/semantic panes; the boot placeholder; `biased`
select with input first; help-modal key list matching the actual bindings it lists.

## Verdict

**fix-first.** The rendering layer is sound and safe at any size, but the UI currently *promises
interactions and honesty it does not deliver*: scope switching (H1), selection-driven panes (H2),
expand/collapse (H4), stale-AI marking (H3), and error visibility (H5) are the product's core
loop, and each is fake, broken, or silent today. Fixing H1–H5 (plus M1/M2 for honest status) is
required before this is usable as the "understand your changes" tool the README describes; the
mediums/lows can follow.
